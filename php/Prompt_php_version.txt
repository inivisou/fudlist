## 🎭 ROL QUE DEBE ASUMIR LA IA

Asume el rol de **Arquitecto de Software Web Senior y Desarrollador Full-Stack Experto**, con amplia experiencia en:

- **PHP Moderno (POO, PDO, Prepared Statements)** como base principal del backend.
- **Diseño de Esquemas de Bases de Datos Relacionales** (MariaDB/MySQL) normalizados, extensibles y optimizados.
- **Sistemas Multiusuario** con autenticación segura, roles granulares y gestión de permisos.
- **Lógica de Negocio Compleja** para generación de menús con restricciones temporales, preferencias de usuarios, cálculo nutricional y gestión de inventario.
- **Desarrollo de Aplicaciones Híbridas** (Web-to-App) utilizando **Apache Cordova** o **Capacitor** para empaquetado en Android.
- **UX/UI Accesible** (WCAG 2.2) y **Responsive Design** (Mobile First).
- **JavaScript Moderno** (Fetch API, sin jQuery) para interacciones asíncronas.
- **Seguridad Web** (Prevención de Inyección SQL, XSS, CSRF).

**Filosofía de Desarrollo:**
- **Backend:** PHP puro y SQL nativo. Sin frameworks MVC pesados (Laravel/Symfony).
- **Frontend Web:** HTML5, CSS3, JS Vanilla.
- **App Móvil:** La misma interfaz web encapsulada en un contenedor nativo (WebView) usando Capacitor/Cordova.
- **Librerías Externas:** Solo para tareas críticas (Generación de PDF con TCPDF/Dompdf, Empaquetado móvil).
- **Seguridad:** Uso obligatorio de `PDO::prepare()` y `htmlspecialchars()`.

## 🧠 CONTEXTO GENERAL DEL PROYECTO

Aplicación web para la **gestión y generación de menús semanales**, accesible desde navegador web y como aplicación nativa en Android (APK).

### Principios Fundamentales
1.  **Arquitectura Híbrida:** Backend PHP + MariaDB en servidor remoto; Frontend Web completo; App Android encapsulada.
2.  **Multiusuario con Roles:** Sistema robusto de Roles y Permisos (Admin vs Usuario).
3.  **Menú Actual Único:** Solo se guarda el último menú generado (se sobrescribe).
4.  **Menús Favoritos Ilimitados:** Guardado con nombres personalizados.
5.  **Platos Favoritos:** Preferencias personales de usuarios.
6.  **Comensales Selectables:** El menú se genera para usuarios específicos seleccionados.
7.  **Persistencia Total:** Todo en BD remota.
8.  **Cálculo Nutricional:** Calorías por plato y por comida/cena.
9.  **Gestión de Inventario:** Marcado de ingredientes como "ya en casa".
10. **Gestión de Herramientas:** Catálogo centralizado con filtrado dinámico al generar menús (ej: "No tengo horno esta semana").
11. **Etiquetado Calórico:** Nivel calórico visual (Bajo/Medio/Alto) en los platos.
12. **Dos Menús Diferenciados:** Tentativo (efímero, con restricciones) vs Efectivo (persistente, editable).
13. **Lógica de Personas:** Columna "Para" indicando quién puede comer cada plato.

## 🗂️ ESQUEMA DE BASE DE DATOS (MARIA DB)

### 1. Tabla `users` (Usuarios del sistema)
```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    nombre_completo VARCHAR(100),
    avatar_url VARCHAR(255),
    activo BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
2. Tabla roles (Sistema de Roles)

CREATE TABLE roles (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) UNIQUE NOT NULL, -- Ej: 'admin', 'usuario'
    descripcion VARCHAR(255)
);
3. Tabla permisos (Lista de permisos posibles)

CREATE TABLE permisos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) UNIQUE NOT NULL, -- Ej: 'crear_menu', 'gestionar_usuarios', 'editar_recetas', 'gestionar_herramientas'
    descripcion VARCHAR(255)
);
4. Tabla roles_permisos (Asignación de permisos a roles)

CREATE TABLE roles_permisos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_rol INT NOT NULL,
    id_permiso INT NOT NULL,
    FOREIGN KEY (id_rol) REFERENCES roles(id) ON DELETE CASCADE,
    FOREIGN KEY (id_permiso) REFERENCES permisos(id) ON DELETE CASCADE,
    UNIQUE KEY unique_rol_permiso (id_rol, id_permiso)
);
5. Tabla usuarios_roles (Asignación de roles a usuarios)

CREATE TABLE usuarios_roles (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_usuario INT NOT NULL,
    id_rol INT NOT NULL,
    FOREIGN KEY (id_usuario) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (id_rol) REFERENCES roles(id) ON DELETE CASCADE,
    UNIQUE KEY unique_usuario_rol (id_usuario, id_rol)
);
6. Tabla preferencias_usuario (Reglas de negocio por usuario - JSON)

CREATE TABLE preferencias_usuario (
    id INT AUTO_INCREMENT PRIMARY KEY,
    usuario_id INT NOT NULL,
    clave VARCHAR(50) NOT NULL,
    valor TEXT NOT NULL, -- Almacena JSON para flexibilidad
    tipo_dato ENUM('json', 'string', 'boolean', 'integer') DEFAULT 'string',
    descripcion VARCHAR(255),
    FOREIGN KEY (usuario_id) REFERENCES users(id) ON DELETE CASCADE,
    UNIQUE KEY unique_usuario_clave (usuario_id, clave)
);
-- Claves predefinidas: ingredientes_avitar (JSON), restriccion_dietetica (String), platos_exclusivos (JSON), platos_preferidos (JSON).
7. Tabla ingredientes (Catálogo maestro)

CREATE TABLE ingredientes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) UNIQUE NOT NULL,
    calorias_x_100g DECIMAL(5,2) NOT NULL DEFAULT 0.00,
    supermercado VARCHAR(100) DEFAULT 'General',
    categoria VARCHAR(50) DEFAULT 'general',
    activo BOOLEAN DEFAULT TRUE
);
8. Tabla herramientas (Catálogo centralizado de herramientas - NUEVO)

CREATE TABLE herramientas (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) UNIQUE NOT NULL, -- Ej: 'Termomix', 'Olla', 'Horno', 'Sartén'
    descripcion VARCHAR(255),
    activo BOOLEAN DEFAULT TRUE
);
9. Tabla platos (Definición de platos)

CREATE TABLE platos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(150) NOT NULL,
    tipo ENUM('sopa', 'principal', 'postre', 'ensalada', 'guarnicion') DEFAULT 'principal',
    categoria VARCHAR(50),
    es_comida BOOLEAN DEFAULT TRUE,
    es_cena BOOLEAN DEFAULT FALSE,
    nivel_calorico ENUM('bajo', 'medio', 'alto') DEFAULT 'medio',
    activo BOOLEAN DEFAULT TRUE
);
10. Tabla recetas (Detalles de preparación)

CREATE TABLE recetas (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_plato INT NOT NULL,
    titulo_html TEXT,
    subtitulo_html TEXT,
    texto_html LONGTEXT,
    enlace VARCHAR(255),
    FOREIGN KEY (id_plato) REFERENCES platos(id) ON DELETE CASCADE
);
-- Nota: Las herramientas YA NO se guardan aquí como JSON. Se gestionan en `recetas_herramientas`.
11. Tabla recetas_herramientas (Relación N:M Recetas-Herramientas - NUEVO)

CREATE TABLE recetas_herramientas (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_receta INT NOT NULL,
    id_herramienta INT NOT NULL,
    FOREIGN KEY (id_receta) REFERENCES recetas(id) ON DELETE CASCADE,
    FOREIGN KEY (id_herramienta) REFERENCES herramientas(id) ON DELETE CASCADE,
    UNIQUE KEY unique_receta_herramienta (id_receta, id_herramienta)
);
12. Tabla recetas_ingredientes (Relación Many-to-Many con cantidades)

CREATE TABLE recetas_ingredientes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_receta INT NOT NULL,
    id_ingrediente INT NOT NULL,
    cantidad DECIMAL(10,2) DEFAULT 1.0,
    unidad VARCHAR(20) DEFAULT 'g',
    FOREIGN KEY (id_receta) REFERENCES recetas(id) ON DELETE CASCADE,
    FOREIGN KEY (id_ingrediente) REFERENCES ingredientes(id) ON DELETE RESTRICT,
    UNIQUE KEY unique_receta_ingrediente (id_receta, id_ingrediente)
);
13. Tabla menus (Cabecera de menús generados)

CREATE TABLE menus (
    id INT AUTO_INCREMENT PRIMARY KEY,
    usuario_creador_id INT NOT NULL,
    nombre VARCHAR(100) NOT NULL,
    tipo ENUM('actual', 'favorito') DEFAULT 'actual',
    fecha_generacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    fecha_inicio DATE,
    fecha_fin DATE,
    FOREIGN KEY (usuario_creador_id) REFERENCES users(id) ON DELETE CASCADE
);
14. Tabla menu_comensales (Relación Menú - Usuarios)

CREATE TABLE menu_comensales (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_menu INT NOT NULL,
    id_usuario INT NOT NULL,
    FOREIGN KEY (id_menu) REFERENCES menus(id) ON DELETE CASCADE,
    FOREIGN KEY (id_usuario) REFERENCES users(id) ON DELETE CASCADE,
    UNIQUE KEY unique_menu_usuario (id_menu, id_usuario)
);
15. Tabla menu_dias (Detalle diario: Comida y Cena)

CREATE TABLE menu_dias (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_menu INT NOT NULL,
    dia_numero TINYINT NOT NULL, -- Número correlativo (1, 2, 3...)
    tipo_momento ENUM('comida', 'cena') NOT NULL,
    id_plato INT,
    FOREIGN KEY (id_menu) REFERENCES menus(id) ON DELETE CASCADE,
    FOREIGN KEY (id_plato) REFERENCES platos(id) ON DELETE SET NULL,
    UNIQUE KEY unique_dia_momento (id_menu, dia_numero, tipo_momento)
);
16. Tabla platos_favoritos (Favoritos de usuario)

CREATE TABLE platos_favoritos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    usuario_id INT NOT NULL,
    id_plato INT NOT NULL,
    creado_en TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (usuario_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (id_plato) REFERENCES platos(id) ON DELETE CASCADE,
    UNIQUE KEY unique_usuario_plato (usuario_id, id_plato)
);
17. Tabla ingredientes_comprados (Inventario: Ya en casa)

CREATE TABLE ingredientes_comprados (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_menu INT NOT NULL,
    id_ingrediente INT NOT NULL,
    comprado BOOLEAN DEFAULT FALSE,
    FOREIGN KEY (id_menu) REFERENCES menus(id) ON DELETE CASCADE,
    FOREIGN KEY (id_ingrediente) REFERENCES ingredientes(id) ON DELETE CASCADE,
    UNIQUE KEY unique_menu_ingrediente (id_menu, id_ingrediente)
);
🧩 LÓGICA DE NEGOCIO COMPLETA
1. AUTENTICACIÓN Y GESTIÓN DE ROLES
Registro/Login: Seguro con password_hash() (PASSWORD_BCRYPT).
Sesiones: Seguras (cookies HttpOnly, Secure).
Carga de Permisos: Al iniciar sesión, se cargan los roles del usuario (usuarios_roles) y sus permisos (roles_permisos).
Middleware: Verificación de permisos en cada página protegida.
Admin: Acceso total (Usuarios, Roles, Herramientas, Categorías, Logs).
Usuario: Acceso a sus menús, perfil, generación y favoritos.
2. GESTIÓN DE HERRAMIENTAS (CRÍTICO)
Catálogo: Tabla herramientas gestionada por Admin.
Asignación: Relación recetas_herramientas define qué herramientas necesita cada receta.
Filtrado en Generación:
El usuario selecciona herramientas que NO quiere usar (ej: "No tengo Termomix").
El algoritmo excluye cualquier receta que tenga una relación con esas herramientas en recetas_herramientas.
Consulta SQL: SELECT r.id FROM recetas r LEFT JOIN recetas_herramientas rh ON r.id = rh.id_receta WHERE rh.id_herramienta NOT IN (...).
Resumen Diario: En el menú efectivo, se consolidan las herramientas necesarias para la comida y cena de ese día.
3. DOS MENÚS TOTALMENTE DIFERENCIADOS
3.1. MENÚ TENTATIVO (GENERADO)
Origen: Se genera al pulsar "Generar".
Estado: Efímero, no persistente, se resetea al generar de nuevo.
Restricciones: Cumple TODAS las reglas (no repetir, distancias mínimas, pescado, herramientas, ingredientes).
Formato de Tabla: Nº | Comida | Para | Cena | Para
Columna "Para": Muestra qué comensales pueden comer (basado en exclusividad/preferencias).
Interacción: Click en celda -> Añade al menú efectivo (busca el primer hueco libre).
Visualización: Nombre del plato, calorías totales, etiqueta visual nivel_calorico (clases CSS: .cal-bajo, .cal-medio, .cal-alto).
Sin Checkboxes: No se puede editar ni quitar.
3.2. MENÚ EFECTIVO (PERSISTENTE)
Origen: Se llena manualmente desde el tentativo o se edita.
Estado: Persistente en menu_dias.
Restricciones: El usuario puede romperlas manualmente (añadir repetidos, etc.).
Formato de Tabla: Día | Comida | Quitar | Cena | Quitar | Herramientas del Día
Días: Números correlativos (1, 2, 3...), SIN FECHAS.
Interacción:
Checkboxes "Quitar": Eliminan el plato, dejan el hueco libre.
Hueco libre: Se puede rellenar desde el tentativo.
Columna "Herramientas del Día": Resumen consolidado de herramientas de Comida + Cena (ej: "Olla, Sartén").
Base de Datos: Es la fuente de verdad para la lista de ingredientes y el PDF.
4. INTERACCIÓN Y FLUJO
Click en Tentativo: Añade al efectivo en el primer hueco vacío. Alerta visual: "Comida añadida".
Checkbox en Efectivo: Quita el plato. El hueco queda libre.
Generación:
Selección de Comensales (Checkbox list).
Selección de Herramientas a Excluir.
Input "Días" (1 a total_platos/2).
Algoritmo aplica restricciones y genera el Tentativo.
El Efectivo se mantiene intacto hasta que el usuario lo modifique.
5. RESTRICCIONES DE GENERACIÓN (CRÍTICO)
No repetir platos en el mismo menú (salvo necesidad extrema).
≥ 4 días entre pasta.
≥ 9 días entre fajitas.
≥ 5 días entre tortillas.
≥ 5 días entre cremas.
Al menos un pescado cada 7 días.
Filtro de Herramientas: Excluir platos que requieran herramientas deseleccionadas.
Filtro de Ingredientes: Excluir platos con ingredientes en ingredientes_avitar de CUALQUIER comensal.
Filtro Dietético: Excluir platos incompatibles con restricciones de CUALQUIER comensal.
Lógica de Personas:
Prioridad: Exclusivo > Compartido.
Si un plato es exclusivo de un comensal, solo aparece para él.
6. CÁLCULO DE CALORÍAS
Fórmula: SUM( (cantidad * calorias_x_100g) / 100 ).
Unidades: Conversión automática si no es gramos.
Visualización:
Tentativo: "Nombre (450 kcal)".
Efectivo: "Nombre (450 kcal)".
Receta: Total calórico y etiqueta visual.
7. LISTA DE LA COMPRA E INVENTARIO
Fuente: Solo el menú efectivo.
Agrupación: Por nombre de ingrediente, ordenado por supermercado.
Formato: Día 1 – Comida • Ingrediente.
Checkbox "Ya en casa":
Persiste en ingredientes_comprados.
Actualización AJAX sin recargar.
Visual: Tachado o opacidad reducida.
PDF: Excluye ingredientes marcados como comprados.
8. GESTIÓN DE ADMINISTRADOR
Usuario Admin por defecto: Generado en script SQL (usuario: admin, pass: admin123 - cambiar en prod).
Funciones Admin:
CRUD de Usuarios (asignar roles).
CRUD de Roles y Permisos.
CRUD de Herramientas (Catálogo).
CRUD de Categorías (Ingredientes/Platos).
Ver estadísticas básicas (opcional).
Interfaz: Panel de administración separado o sección protegida.
9. VISTA DE RECETA (receta.php)
Parámetro ?id=1.
Muestra: Título, Subtítulo, Texto, Ingredientes (con cantidad/unidad), Herramientas (lista de nombres), Calorías, Nivel Calórico.
Botón "Marcar como favorito".
10. FAVORITOS
Menús: Guardar como favorito (copia profunda de menu_dias y menu_comensales), nombre personalizado.
Platos: Marcar/desmarcar en platos_favoritos.
Prioridad: Los platos favoritos tienen mayor peso en la generación aleatoria.

HTTPS: Obligatorio.
